# Council review: Claude Opus 5.5

Reviewed the v0.3 draft of `docs/dev/DESIGN-v0.3-server-side.md` on 2026-09-28, read-only, with
web access to official docs. Brief: [`brief.md`](brief.md). Verbatim final answer:

## Verdict
**Revise before implementing.** The layering idea and the "compile only the verified subset, report coverage" principle are right, but the design rests on a false premise: that scoping enforcement to *agent identities* makes it complete. As written, an agent can shed its identity (launch a Pod/Job/CronJob under a non-agent ServiceAccount, `exec` into an existing pod, impersonate, assume/pass a role to Lambda/CloudFormation/CodeBuild, impersonate a GCP SA, push to GitOps and let a controller apply it) or strip its own controls (edit the webhook's own namespace — which the spec *excludes* via `namespaceSelector` — mutate `ValidatingWebhookConfiguration`s, on which webhooks are never called, or detach its own IAM deny). **Single most important change: add an "agent identity closure" section as a hard prerequisite for every enforcement point** — an inventory of every path by which an agent identity can act as / create a non-agent identity or modify its own controls, each denied by the generated artifacts themselves (or reported uncovered), plus a deny-by-default mode ("everyone not in the human/controller list is an agent").

## Findings
1. **[P0] Identity laundering defeats identity scoping** — §3.2, §4.2, §5.4. An agent that can create Pods/Jobs/Deployments runs `kubectl`/SDK under any SA in that namespace; `pods/exec` into a privileged pod, `impersonate`, `serviceaccounts/token` create, `nodes/proxy` do the same. AWS: `sts:AssumeRole` into a non-agent role, `iam:PassRole` to Lambda/ECS/EC2/CodeBuild/CloudFormation service role. GCP: `iam.serviceAccounts.getAccessToken`/`actAs`, Cloud Build. Azure: managed identities on VMs/Automation. GitOps: Argo/Flux apply under their own identity. **Fix:** a required "identity closure" section; generated denies for the escape permissions (or a coverage line saying they are uncovered); webhook rules for Pod/Job/CronJob `spec.serviceAccountName`, `impersonate`, token requests; an `aegis audit-identity` check (SubjectAccessReview / IAM simulator) documented as a precondition.
2. **[P0] Self-protection is missing** — §4.2, §4.5, §5.4. The `namespaceSelector` excludes the webhook's own namespace and `kube-system`: an agent with RBAC there swaps the Deployment image/args, replays an older signed ConfigMap, or deletes CoreDNS unchecked. Admission webhooks are never called on `ValidatingWebhookConfiguration`/`MutatingWebhookConfiguration`, so an agent with `admissionregistration` rights simply deletes it (confidence high). AWS: an identity-policy Deny is removed by an agent holding `iam:DetachRolePolicy/PutRolePolicy/DeleteRolePolicy` on its own role; GCP `iam.denypolicies.*`; Azure `Microsoft.Authorization/locks/delete`, `roleAssignments/write`. **Fix:** drop the namespace exclusions (matchConditions already scope to agents; exclusions buy nothing and open a hole); every compiled output includes denies on modifying the controls themselves (IAM on agent roles and the deny policy, SCP detach, deny-policy admin, lock/role-assignment writes); document required RBAC; prefer SCP/permissions boundary over identity policy when the agent has any IAM rights.
3. **[P0] Deny + conditions fail open on missing keys** — §5.2 `scope.env` → `aws:ResourceTag/env`. A Deny with `StringEquals` on a key absent from the request context does not apply: untagged prod resources and actions that don't support `aws:ResourceTag` are silently unprotected; an agent with `UntagResource`/`TagResource` removes the tag first. **Fix:** compile `env` from `environments.yaml`'s account/project/subscription mapping (Aegis already resolves env that way), not tags; tags only as operator opt-in, with denies on un/retagging the env key (`aws:TagKeys`) and a per-action "key supported" field; `approximated` must carry a direction (over-block vs under-block), and under-block must be reported as `not expressible`.
4. **[P1] GCP section is factually wrong in two places** — §5.3, §5.4. Deny policies name permissions as `SERVICE_FQDN/RESOURCE.ACTION` (e.g. `cloudresourcemanager.googleapis.com/projects.delete`), not `resourcemanager.projects.delete`; only a subset of permissions is deniable; and denial conditions "only recognize resource tag functions", so resource-**name** patterns (`sql/instance/prod-*`) are not expressible in GCP deny policies — they are over-approximated to the attachment point (project/folder) or require tags. 500 deny policies and 500 deny rules total per resource. Verified: https://docs.cloud.google.com/iam/docs/deny-overview. The §5.2 row "Deny on … resource ARNs / names" is false for GCP. Principal formats: `principal://iam.googleapis.com/projects/-/serviceAccounts/…`, `principalSet://goog/group/…` (high confidence, not fetched).
5. **[P1] Azure section is outdated/incomplete** — §5.4. "Deny assignments are only created by Azure for managed applications and blueprints" is outdated: users can't create them directly, but **deployment stacks** with `denySettings` (`denyDelete`/`denyWriteAndDelete`) create deny assignments that apply to all principals except up to 5 excluded principals (groups allowed) and 200 excluded actions. Verified: https://learn.microsoft.com/en-us/azure/role-based-access-control/deny-assignments and https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deployment-stacks. That gives a real, Owner-proof deny scoped "everyone except the humans/break-glass group" for named, stack-managed resources. Custom-role `NotActions` is **not a deny** — any other role assignment the managed identity holds (Contributor at a parent scope, etc.) grants it back; the spec must require that role be the identity's only assignment and deny `Microsoft.Authorization/*/write`. Correct in spec: Azure Policy deny/denyAction cannot condition on the caller; denyAction is delete-only.
6. **[P1] Resource normal form from `kind.kind` is wrong for subresources** — §4.3. For `deployments/scale`, `kind` is `Scale`; `pods/eviction` → `Eviction`; exec → `PodExecOptions`. `name` is empty on generateName CREATEs and, I believe, on per-item deletecollection admission (UNSURE, ~70%: `AdmissionToValidateObjectDeleteFunc` reuses the static attributes' empty name; name is on `oldObject`). `lower(kind)` also collides across API groups (Knative `Service` vs core `Service`). **Fix:** derive kind from `request.resource` (GVR) + subresource through one shared, versioned table; take name from `oldObject`/`object` metadata when `request.name` is empty; include group (e.g. `params.api_group`).
7. **[P1] Action vocabulary doesn't line up with the CLI** — §4.3. The kubectl parser keeps raw verbs (`patch`, `apply`, `edit`, `cordon`, `drain`, `taint`, `rollout-restart`, `set-image`, `label`, `port-forward`); admission only sees CREATE/UPDATE/DELETE/CONNECT. A policy saying `actions: [drain]` or `[rollout-restart]` never fires in the webhook; `port-forward` is mapped to `exec` in the spec but is `port-forward` in the CLI. **Fix:** define a canonical K8s action set with object-diff derivations (cordon = `spec.unschedulable` true; drain = eviction CREATE; restart = `restartedAt` annotation; set-image = container image diff), normalise both parsers to it, and make the coverage report cover the **webhook** too (not only compiled targets, Goal 3) — including scope keys taken from CLI `params` the webhook cannot derive (a rule scoped on an absent key never matches = silent gap).
8. **[P1] "Exactly one intent per request" breaks parity on namespace delete** — §4.3. The CLI emits the synthetic `*/*` cascade intent (parser.py `_namespace_cascade_intents`); the webhook as specified does not, so `scope: {namespace: prod}` rules with `resource_pattern: '*'`/`'*/*'` diverge. Also factually imprecise: namespace-controller deletes **do** go through admission, under `system:serviceaccount:kube-system:namespace-controller`, which `matchConditions` filter out (same for the GC cascade after deleting a Deployment). **Fix:** emit the same cascade intent for a Namespace DELETE; allow a list of intents per request.
9. **[P1] The HMAC signing key would sit in a network-exposed pod** — §4.5. PLAN §8: signatures are shared-secret BLAKE2b MACs — whoever can verify can sign. Mounting the key in the webhook (and the `compile --check` CI job) puts policy-forging capability in the cluster (anyone who can `get secrets` in that namespace or compromise the pod). Contradicts the core trust model. **Fix:** make PLAN §9 item 2 (public-key signing) a prerequisite of v0.3.0, or support Git-signed sources only in the webhook (those verify with public keys).
10. **[P1] No rollback/freeze protection on reload** — §4.5. A validly signed *older* constraints file + `.sig` can be replayed into the ConfigMap (the v0.2 freshness check only covers Git). An attacker who can push unsigned junk can push the quarantine ratio over the threshold and freeze reloads on the old store indefinitely. The Git sidecar's in-place fetch races the loader. **Fix:** monotonic policy version / minimum `constraints_sha256` or commit ancestry check; a max-staleness that turns readiness false (with alert); fetch into a new worktree and swap atomically.
11. **[P1] Interceptor settings for the webhook are unspecified.** `on_untrusted_match=escalate` + ESCALATE→deny means a quarantined (poisoned) rule can deny — contradicting "an unverified constraint gets no vote"; pin `discard`. `fail_closed` (uncovered→ESCALATE→deny for every agent write), `env-unresolved` and `time-window-unresolved` all become denies. The rate-limit ledger is per replica — with ≥2 replicas limits are multiplied; needs a shared ledger or `rate_limit` reported as not enforced by the webhook.
12. **[P1] Generating webhook `rules` from policy creates drift** — §4.2. A rule for a new kind/CRD lands and the registration isn't updated until someone redeploys: silent gap. **Fix:** register `*/*` for all operations incl. CONNECT and needed subresources (volume is already bounded by agent `matchConditions`), or add a drift check comparing registration against policy.
13. **[P1] §5.1/§5.6 contradict each other on drift.** "Aegis never holds cloud credentials" vs "stale warning when a deployed manifest's sha no longer matches" — reading the deployed policy needs cloud read access. Committed-output drift ≠ live drift (console edits, an agent detaching the policy). **Fix:** a documented read-only verification job (operator credentials) that diffs the live policy against compiled; a place to carry the sha (policy `Sid`/description/tags).
14. **[P2] AWS limits not handled** — §5.4. Managed policy 6,144 chars; default 10 managed policies per role; SCP 5,120 chars and 5 SCPs per target (high confidence, not fetched). The compiler needs chunking and must fail loudly on overflow. SCPs also don't affect service-linked roles. `aws:RequestedRegion` for global services is `us-east-1` (UNSURE per-service).
15. **[P2] Semantic-equivalence gaps in the action map** — §5.3. Blocking `s3:DeleteBucket` doesn't stop emptying it (`DeleteObject`) or expiring it via lifecycle (`PutLifecycleConfiguration`); blocking RDS delete doesn't stop `ModifyDBInstance DeletionProtection=false` then other paths, or `kms:ScheduleKeyDeletion`. The coverage report should list "same-effect actions not covered" per rule. fnmatch `[...]` classes have no IAM equivalent — must be reported; case sensitivity (PLAN §8 xfail) differs per cloud.
16. **[P2] ESCALATE message steers the agent wrongly** — §4.4. "Retry as a human identity" invites the model to hunt for human credentials or `--as`. **Fix:** "needs human approval; stop and hand off".
17. **[P2] Webhook hardening** — §4.1. Python's stdlib `http.server` is documented as not for production: needs body-size limits, header/read timeouts, TLS cert hot-reload (cert-manager rotation), a NetworkPolicy, and optionally verifying the API server's client cert (AdmissionConfiguration kubeconfig) — otherwise any pod can send forged AdmissionReviews to probe policy and pollute the audit log. Logs must never include `object` (Secret payloads arrive in AdmissionReview).
18. **[P2] dryRun requires `sideEffects: None`/`NoneOnDryRun`** — otherwise the API server rejects dry-run requests outright; say so explicitly.
19. **[P2] Existing parser bugs will surface in the parity corpus — fix first.** From running the current parser (read-only): `kubectl delete storageclasses fast` → `storageclasses/fast` (plural kept; webhook would say `storageclass/fast`), same for `ingressclasses`; `kubectl drain node1` → `node1/*` (should be `node/node1`); `endpoints` has no singular.
20. **[P3] Warnings size** — the API server may truncate long warnings; keep quarantine warnings short.
21. **[P3] GitHub rulesets** apply to everyone except bypass actors and have plan limits on private repos; say so in coverage.
22. **[P3] Consider ValidatingAdmissionPolicy (CEL, GA 1.30) as a compile target** for simple, identity-scoped K8s rules — in-process in the API server, no availability or key exposure; the webhook stays for time windows, rate limits and full-engine rules.

## Open questions (§10)
1. **deletecollection:** Assume per-item DELETE with `oldObject` populated, but take the name from `oldObject.metadata.name` because `request.name` may be empty (UNSURE); verify on `kind` per supported minor as a test, not an assumption. Reason: per-item path is the generic registry behaviour; the empty name is the likely trap.
2. **ESCALATE:** Deny, with a hand-off message (not "retry as human"); a per-rule opt-in `webhook_escalate: warn` later. Reason: an agent identity has no approval channel; allow-with-warning turns ESCALATE into ALLOW.
3. **Time windows:** Report `not expressible`, opt-in `--time-window=always` over-approximation; no scheduler. Reason: the scheduler needs cloud write creds (contradicts §5.1), fails open when it breaks, and GCP deny conditions can't express time at all; AWS absolute-time statements expire open.
4. **Azure:** Don't ship `NotActions` as "enforcement". Ship deployment-stack deny settings for named critical resources (real deny, humans in the excluded group) plus an optional least-privilege role labelled as such; defer the rest to the broker. Reason: NotActions is revoked by any other role assignment.
5. **`agents.yaml`:** Signed policy directory with its own authority class in `authority.yaml`; generate `matchConditions` from it; add a check that flags RBAC drift. Not derived from RBAC. Reason: RBAC is mutable outside Aegis's trust chain, and SAs can't carry custom groups like `aegis:agents` — scoping must use `system:serviceaccount:<ns>:<name>` / `system:serviceaccounts:<ns>`; offer a deny-by-default inversion listing humans/controllers instead.
6. **K8s version:** Require ≥1.30, drop the fallback. Reason: all upstream-supported minors are ≥1.30 by now, and the fallback (no matchConditions + `failurePolicy: Fail`) makes a webhook outage block **every** write, humans and controllers included — contradicting §4.6's safety argument.

## Missing from the spec
- Agent identity closure / escape-path inventory and self-protection denies (Findings 1–2).
- Coverage report for the webhook itself; canonical K8s action vocabulary shared with the CLI.
- Interceptor configuration for server-side points (`on_untrusted_match`, `fail_closed`, ledger sharing).
- Key-management prerequisite (public-key signing) and rollback/freeze protection.
- Live-state drift verification and where the provenance sha lives inside each cloud artifact.
- Per-cloud size/count limits and chunking.
- Direction of approximation (over- vs under-block) as a first-class coverage field.
- Controller-mediated effects (GC, HPA, GitOps, CloudFormation/Deployment Manager) as explicit coverage lines.
- Break-glass: what happens when a bad compiled deny or webhook locks agents out, and who can bypass.
- Log hygiene for AdmissionReview payloads (Secrets).
- **Phasing:** move `compile aws` (static, no runtime/availability risk, covers the SDK/console bypass that motivated §1) to v0.3.0 alongside — or before — the webhook if public-key signing isn't ready; cut GitHub rulesets and Azure from v0.4.0 unless the deployment-stack approach is adopted; make the identity-closure check and the parser normal-form fixes part of v0.3.0.
